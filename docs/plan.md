# План доработок

## 1. Сейчас: перед сменой машины

- **Зачем:** e2-micro долго держит примерно 15–30 Мбит/с на всех (≈ 25% одного
  процессора). Это главный потолок скорости.
- **Как:** «🛠 Техработы» → остановить машину → сменить тип → запустить →
  проверить `systemctl status geoirb-vpn-bot`, контейнер `amnezia-awg2`, людей онлайн →
  «✅ Работы закончены».
- Диск тот же, поэтому настройки сервера (`/etc/sysctl.d/99-geoirb-vpn.conf`,
  `geoirb-vpn-mss.service`) сохранятся.
- Смотреть на уведомления «⚠️ Сервер: процессор …» — их не должно быть.
- Оценка «15–30 Мбит/с» была для `amneziawg-go`. С 28.09 VPN работает в ядре (2.1), процессора
  на тот же трафик нужно меньше: менять машину, если всё равно приходят уведомления о процессоре.

## 2. Скорость VPN

### 2.1. Модуль ядра AmneziaWG вместо `amneziawg-go` — ✅ сделано 28.09.2026
- VPN работает в ядре: `ip -d link show awg0` в контейнере показывает `amneziawg`,
  `amneziawg-go` не запущен. Параметры 2.0 (`S3/S4`, `H1–H4`) модуль принимает.
- Модуль: `amneziawg-dkms` из `ppa:amnezia/ppa` (DKMS, пересобирается при обновлении ядра).
  Мета-пакет `amneziawg` на 26.04 не ставится (нет `amneziawg-tools`) — он и не нужен,
  утилиты `awg` есть в контейнере.
- Автозагрузка: `/etc/modules-load.d/amneziawg.conf` (ставит `deploy/install.sh`).
- **На новом сервере** модуль ставится вручную, до первого запуска контейнера:
  `add-apt-repository ppa:amnezia/ppa && apt install amneziawg-dkms`.
- **Откат:** удалить `/etc/modules-load.d/amneziawg.conf`, в контейнере
  `awg-quick down /opt/amnezia/awg/awg0.conf`, `modprobe -r amneziawg`,
  `docker restart amnezia-awg2` — VPN снова пойдёт через `amneziawg-go`.


### 2.2. MTU 1380 для сервера и клиентов
- **Зачем:** пакет VPN снаружи ~1492 байт, а сеть GCP пропускает 1460 — большие пакеты
  режутся. `geoirb-vpn-mss.service` уже чинит TCP, но не UDP (звонки, QUIC).
- **Код:** бот не копирует `MTU` из конфига сервера (`serverOnlyKeys` в
  `internal/vpn/amnezia/conf.go`). Нужна настройка `CLIENT_MTU` (пусто = не писать),
  которую `RenderClient` пишет в `[Interface]` клиента. Тесты: MTU есть в конфиге, когда
  задан, и нет, когда пусто.
- **Сервер:** `MTU = 1380` в `[Interface]` конфига сервера и `ip link set awg0 mtu 1380`.
- **Потом:** «🔄 Обновить конфиги».
- Делать в окне техработ пункта 4 — там VPN всё равно перезапускается.

## 3. При переезде на новый сервер

### 3.1. Домен в `ENDPOINT_HOST`
- **Зачем:** при смене IP меняется только DNS-запись, конфиги у людей остаются рабочими,
  рассылка «обновите ключ» не нужна.
- **Как:** A-запись, например `vpn.<домен>` → IP сервера; `ENDPOINT_HOST=vpn.<домен>`;
  `make deploy`; «🔄 Обновить конфиги» — один раз, последний.

### 3.2. Шаги переезда
- В README, раздел «Перенос на другой сервер». Настройки сервера для нагрузки
  (`deploy/99-geoirb-vpn.conf`, `geoirb-vpn-mss.service`) ставит `make deploy`.

## 4. VPN без Docker и сильнее маскировка — одно окно техработ

VPN всё равно перезапускается, а конфиги у людей меняются один раз. Лучше делать при
переезде (3), вместе с доменом (3.1) и MTU (2.2): одна рассылка «🔄 Обновить конфиги».

**Порядок в окне:** свежий бэкап и «🛠 Техработы» → 4.1 **со старыми параметрами** и
проверка → 4.2 и 2.2 (новые параметры) → свой ключ на телефоне → «🔄 Обновить конфиги» →
«✅ Работы закончены». 4.1 и 4.2 раздельно: если что-то сломалось, ясно, что именно.

### 4.1. VPN прямо на хосте, без контейнера Amnezia (аудит 27.09, L35)
- **Зачем:** `vpnbot` в группе `docker`, а доступ к Docker = root на машине. Защита
  systemd (`NoNewPrivileges`, `ProtectSystem`) это не останавливает: взлом бота сейчас =
  взлом всей машины. А контейнер Amnezia — это только `awg-quick`, один конфиг и правила
  iptables; VPN и так работает в ядре хоста (2.1).
- **Почему не обёртка `geoirb-awg` над `docker exec`** (прошлый план): она нужна была
  только из-за привилегированного контейнера. Без контейнера она не нужна, и кода меньше.
- **Сервер** (`deploy/install.sh`):
  1. `awg`/`awg-quick` на хосте. Пакет `amneziawg-tools` на 26.04 не ставится → собрать из
     исходников `github.com/amnezia-vpn/amneziawg-tools` (фиксированный тег).
  2. Перенести `/opt/amnezia/awg/awg0.conf` из контейнера на хост как есть (путь — тот,
     где его ищет `awg-quick`, проверить). Ключ сервера, порт, `Jc/S/H/I` и пиры те же →
     клиенты ничего не замечают.
  3. `awg-quick@awg0.service`. В `PostUp`/`PostDown`: `ip_forward`, MASQUERADE на внешний
     интерфейс, FORWARD для `awg0`. Проверить, что `geoirb-vpn-mss.service` работает с
     хостовым `awg0`, и убрать из него зависимость от `docker.service`.
  4. Удалить таймер conntrack (`geoirb-vpn-conntrack.*`, `awg-conntrack.sh`,
     `scripts/awg-conntrack_test.sh`): VPN в сети хоста, копировать таймаут некуда.
  5. `backup.sh`: брать `awg0.conf` с хоста, а не `docker exec` (Mongo остаётся в Docker).
  6. Контейнер `amnezia-awg2`: остановить и `docker update --restart=no`, **не удалять**
     до конца проверок — это откат.
- **Бот** (сначала тесты):
  1. `LocalRunner` вместо `DockerRunner`: те же команды `awg` и работа с файлом, но на
     хосте. Права: `AmbientCapabilities=CAP_NET_ADMIN` в unit (для `awg show/syncconf`),
     конфиг — владелец `vpnbot`, `0600`. `NoNewPrivileges` остаётся, sudo не нужен.
  2. Удалить: `DetectContainer`, `awg-container.sh`, `clientsTable` (`clients.go` и вызовы
     в `vpn.go`), `SupplementaryGroups=docker`, `ReadWritePaths=/run/docker.sock`,
     `Wants/After=docker.service`, `usermod -aG docker`.
  3. Настройка `AWG_CONF` (путь к конфигу) вместо имени контейнера. Локальный запуск
     (`DOCKER_BIN=scripts/dev-docker.sh`) заменить ssh-обёрткой для команд на хосте.
  4. Проверка sha перед записью остаётся — защита от ручных правок файла.
  5. Тесты: `LocalRunner` с фейковым `awg` в `PATH`.
- **Теряем:** управление сервером из приложения Amnezia (оно ходит в контейнер).
  Обновления AWG — сами: модуль через apt, утилиты — пересборка по новому тегу.
- **Проверка:** выдать ключ, отключить, включить, удалить, перевыпустить, `Reconcile`
  без расхождений, люди онлайн (`awg show`), бэкап проходит.
- **Откат:** `systemctl disable --now awg-quick@awg0`, `docker update --restart=always
  amnezia-awg2 && docker start amnezia-awg2`, прошлый бинарник и unit (`git revert`,
  `make deploy`). Ключи, выданные после перехода, есть только в хостовом конфиге —
  перед откатом скопировать его в контейнер.

### 4.2. Сильнее маскировка (AmneziaWG 2.0)
- **Зачем:** сейчас `H1–H4 = 1, 2, 3, 4` (значения по умолчанию) — такой трафик проще
  распознать DPI.
- **Граница:** клиентов пишем не мы (Amnezia VPN, AmneziaWG). Меняем только параметры,
  которые понимают их приложения; свой протокол — нет.
- **Сначала (только чтение):** выписать с сервера `Jc/Jmin/Jmax`, `S1–S4`, `H1–H4`,
  `I1–I5`, порт. Сверить с документацией AmneziaWG 2.0: какие форматы принимают модуль и
  приложения (диапазоны в `H1–H4`, формат `I1`).
- **Что меняем:**
  1. `H1–H4` — случайные и не пересекающиеся (диапазоны, если 2.0 их поддерживает).
  2. `I1` — пакет под QUIC Initial (или DNS); `I2–I5` — если нужно. Бот уже переносит их
     в клиентов раскомментированными.
  3. `S1–S4`, `Jc/Jmin/Jmax` — не значения по умолчанию; размеры с учётом MTU (2.2).
  4. Порт UDP 443 — вместе с `I1` под QUIC трафик похож на HTTP/3. Открыть в firewall GCP.
- **Код:** параметры и так идут из `[Interface]` сервера в клиентов (`serverOnlyKeys`).
  Тест: новые значения (диапазон в `H1`, длинный `I1`) попадают в клиентский конфиг без
  изменений, а `awg syncconf` получает то, что принимает.
- **Проверка до рассылки:** свой ключ в Amnezia VPN и AmneziaWG, iOS и Android, мобильная
  сеть и Wi‑Fi.
- Ломает все текущие конфиги → только в одно окно с 4.1.

### 4.3. Не делаем
- Свой протокол или форк клиентов — клиентов пишем не мы.
- Всё на Go (netlink вместо `awg`) — неясно, поддерживают ли Go-библиотеки параметры 2.0,
  а выигрыш маленький.
- Второй протокол поверх TCP/443 (VLESS + Reality) — только если UDP начнут блокировать
  целиком. Отдельная большая задача.
