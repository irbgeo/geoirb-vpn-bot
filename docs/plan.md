# План доработок

Состояние на 27.09.2026. Бот работает на сервере (GCP e2-micro, `35.217.30.38`),
последний коммит в `main` — `3fa9e0d`. Пункты идут по порядку: сверху — то, что
нужно сделать раньше.

## 1. Сейчас: перед сменой машины

### 1.1. Закрепить внешний IP — до остановки машины
- **Зачем:** `ENDPOINT_HOST=35.217.30.38` — IP прямо в конфигах всех клиентов. Если
  внешний IP у машины временный (ephemeral), после остановки GCP выдаст новый, и VPN
  перестанет работать у всех.
- **Как:** GCP → VPC network → IP addresses → у адреса машины «Promote to static IP
  address». Или `gcloud compute addresses create … --addresses 35.217.30.38`.
- **Проверка:** адрес в списке помечен как Static.

### 1.2. Задеплоить исправления второго аудита
- 40 из 41 пункта (L35 — в 4.1). Деплой теперь идёт через `deploy/install.sh` и
  делает бэкап **до** перезапуска бота: первый `make deploy` после этого проверяет и сам
  новый порядок. Упадёт бэкап — старый бот продолжит работать.
- После деплоя: `systemctl status geoirb-vpn-conntrack.timer`, в контейнере
  `cat /proc/sys/net/netfilter/nf_conntrack_tcp_timeout_established` = 7200.

### 1.3. Сменить машину на более мощную
- **Зачем:** e2-micro долго держит примерно 15–30 Мбит/с на всех (≈ 25% одного
  процессора). Это главный потолок скорости.
- **Как:** «🛠 Техработы» → остановить машину → сменить тип → запустить →
  проверить `systemctl status geoirb-vpn-bot`, контейнер `amnezia-awg2`, людей онлайн →
  «✅ Работы закончены».
- Диск тот же, поэтому настройки сервера (`/etc/sysctl.d/99-geoirb-vpn.conf`,
  `geoirb-vpn-mss.service`) сохранятся.
- Смотреть на уведомления «⚠️ Сервер: процессор …» — их не должно быть.

## 2. Скорость VPN

### 2.1. Модуль ядра AmneziaWG вместо `amneziawg-go`
- **Зачем:** меньше процессора на тот же трафик, ниже задержка.
- **Как устроено:** `awg-quick` в контейнере сначала пробует `ip link add awg0 type
  amneziawg` и только без модуля запускает `amneziawg-go`. Достаточно поставить модуль
  на хост и перезапустить контейнер.
- **Риск:** сервер использует параметры AmneziaWG 2.0 (`S3`, `S4`). В официальном
  репозитории модуля их пока нет (issue #169). В `ppa:amnezia/ppa` есть сборка для
  Ubuntu 26.04 от 14.09.2026, но поддержка 2.0 не подтверждена.
- **Шаги:**
  1. `add-apt-repository ppa:amnezia/ppa && apt install amneziawg` (DKMS, ядро 7.0).
     Рабочий VPN это не трогает.
  2. Тест в контейнере: создать `awgtest` типа `amneziawg` с нашими `Jc/Jmin/Jmax/S1–S4/H1–H4`,
     без клиентов, и удалить. Не приняло параметры → снять модуль, остановиться.
  3. «🛠 Техработы» → `docker restart amnezia-awg2` → `ip -d link show awg0` в контейнере
     показывает тип `amneziawg` → люди онлайн → «✅ Работы закончены».
  4. `deploy/`: файл для `/etc/modules-load.d/amneziawg.conf`, чтобы модуль грузился при старте.
- **Откат:** `modprobe -r amneziawg` + перезапуск контейнера. Если после обновления ядра
  модуль не соберётся, `awg-quick` сам вернётся к `amneziawg-go`.

### 2.2. MTU 1380 для сервера и клиентов
- **Зачем:** пакет VPN снаружи ~1492 байт, а сеть GCP пропускает 1460 — большие пакеты
  режутся. `geoirb-vpn-mss.service` уже чинит TCP, но не UDP (звонки, QUIC).
- **Код:** бот не копирует `MTU` из конфига сервера (`serverOnlyKeys` в
  `internal/vpn/amnezia/conf.go`). Нужна настройка `CLIENT_MTU` (пусто = не писать),
  которую `RenderClient` пишет в `[Interface]` клиента. Тесты: MTU есть в конфиге, когда
  задан, и нет, когда пусто.
- **Сервер:** `MTU = 1380` в `[Interface]` конфига сервера и `ip link set awg0 mtu 1380`.
- **Потом:** «🔄 Обновить конфиги».
- Делать вместе с 2.1 или 3.1 — там VPN всё равно перезапускается.

## 3. При переезде на новый сервер

### 3.1. Домен в `ENDPOINT_HOST`
- **Зачем:** при смене IP меняется только DNS-запись, конфиги у людей остаются рабочими,
  рассылка «обновите ключ» не нужна.
- **Как:** A-запись, например `vpn.<домен>` → IP сервера; `ENDPOINT_HOST=vpn.<домен>`;
  `make deploy`; «🔄 Обновить конфиги» — один раз, последний.

### 3.2. Сильнее обфускация (H1–H4)
- Сейчас `H1–H4 = 1, 2, 3, 4` (значения по умолчанию) — такой трафик проще распознать.
- Смена ломает все текущие конфиги → только при переезде, вместе с 3.1 и 2.2, одной
  рассылкой «🔄 Обновить конфиги».

### 3.3. Шаги переезда
- В README, раздел «Перенос на другой сервер». Настройки сервера для нагрузки
  (`deploy/99-geoirb-vpn.conf`, `geoirb-vpn-mss.service`) ставит `make deploy`.

## 4. Безопасность

- **Утёкший ключ iPhone** (`Admin [iOS 26.6.1]`, 10.8.1.1): поставить на iPhone ключ
  `tg:geoirb #3` (10.8.1.11) из «📋 Мой доступ», проверить, удалить 10.8.1.1 в карточке.
- **SSH:** ключ вместо пароля для `admin_vpn`, пароль сменить (он был в чате).
- **Токен бота** был в логах до исправления go-tgbot: `/revoke` в @BotFather, новый токен
  в `.env`, `FORCE=1 make deploy` (деплой защищает токен от случайной смены).

### 4.1. Бот без группы `docker` (аудит 27.09, L35)
- **Зачем:** `vpnbot` в группе `docker`, а доступ к Docker = root на машине. Защита
  systemd (`NoNewPrivileges`, `ProtectSystem`) это не останавливает. Путей атаки через
  Telegram аудит не нашёл (команды идут списком аргументов, без shell), но взлом бота
  сейчас = взлом всей машины.
- **Почему не прокси к Docker:** контейнер Amnezia привилегированный, и любой
  `docker exec` в нём — тоже root на хосте. Защищает только набор **фиксированных**
  команд.
- **Что бот делает в контейнере сейчас** (`internal/vpn/amnezia`): `awg genkey/pubkey/
  genpsk`, `awg show … public-key|dump`, `cat` конфига и `clientsTable`, `ls` папки
  конфига, и два своих `sh -c` скрипта — сохранение файла (`.bak` → `.tmp` → `mv`,
  проверка sha256) и `awg syncconf`.
- **План:**
  1. Root-скрипт `/usr/local/sbin/geoirb-awg` (из `deploy/`) с подкомандами вместо
     произвольных команд: `genkey`, `pubkey` (stdin), `genpsk`, `server-pubkey`, `dump`,
     `read-conf`, `read-clients`, `write-conf <sha>` и `write-clients <sha>` (stdin; сам
     делает `.bak`/`.tmp`/`mv` и сверку sha), `syncconf` (stdin). Имя контейнера — из
     `awg-container.sh`. Входные данные проверяются: только нужные символы, лимит размера.
  2. `sudoers`: `vpnbot ALL=(root) NOPASSWD: /usr/local/sbin/geoirb-awg`.
  3. Новый `Runner` в адаптере вызывает `sudo -n geoirb-awg <подкоманда>` вместо
     `docker exec`; логика сохранения переезжает из Go-скриптов в обёртку.
  4. Убрать `SupplementaryGroups=docker` и `ReadWritePaths=/run/docker.sock` из unit,
     `usermod -aG docker` из `install.sh`; `NoNewPrivileges` придётся снять (нужен sudo) —
     вместо него узкое правило sudoers.
  5. Тесты: обёртка — скриптовый тест с фейковым `docker` (как `awg-conntrack_test.sh`);
     адаптер — тесты на новый `Runner`.
- **Риск:** меняется путь каждой правки VPN. Делать в спокойное время, с «🛠 Техработы»,
  свежим бэкапом и проверкой: выдать ключ, отключить, включить, удалить, `Reconcile`.
- **Откат:** вернуть прошлый бинарник и unit (`git revert`, `make deploy`).

## 6. Бот: новые возможности (по желанию)

- **Уведомление о трафике:** сейчас бот следит за таблицей соединений, памятью, диском и
  процессором; можно добавить скорость сети относительно предела машины.
- **Дополнительное устройство** (+100 ⭐/мес): модель данных уже позволяет несколько
  ключей на человека, нужен экран и тариф.
- **Возврат звёзд самим пользователем** (`/refund`, как в blacks-law-bot) — не добавлен.

## 7. Масштаб (когда понадобится)

- **Несколько серверов:** `server_id` уже хранится. Нужно: выбор сервера при выдаче,
  `keys_count` — сумма по всем серверам (сейчас Reconcile считает только свой),
  Reconcile на каждом сервере.
- **Второй протокол** (например, Xray/VLESS): код лежит в `internal/vpn/<протокол>`, но
  сервис пока говорит на языке AmneziaWG (`*amnezia.ServerConf`, `FreeIP`, `AddPeer`).
  Сделать порт независимым от протокола и добавить `protocol` в документ ключа.
